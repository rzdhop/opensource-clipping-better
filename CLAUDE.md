# rzdhop AI — context for every Claude session

Read this first. It is the single source of context; `.claude/CHECKPOINT.md` says where the work stands today.

## What this repo is

Two independent products in one repo, owned by **Rida** (rzdhop):

1. **Clips** — long video → vertical short clips (karaoke subtitles, face-tracked framing, B-roll, BGM, hooks,
   metadata). CLI `main.py` + web app (`web/api` FastAPI, `web/dashboard` React) run with `docker compose` on Rida's
   VPS (CPU only, reached over Tailscale). Analysis runs on a chain of hosted LLMs (`LLM_CHAIN`, mostly free tiers).
2. **AI stories (showrunner)** — serialized vertical episodes (fruit dramas and any other universe). Claude, in a
   claude.ai chat, writes and directs with the skill **`rzdhop-story`**; the **`showrunner`** MCP connector is its
   hands: pictures (FLUX.2 klein), speaking clips (LTX-2.5, picture + voice together), locked voices (Chatterbox
   voice conversion) on RunPod Serverless, the clip check (speech-to-text on the host CPU) and the cut. The dashboard
   has no story pages: stories are made only in the chat. The old in-app "AI Story" mode was deleted (DEC-332).

## Host (Rida's VPS)

- Web app: `docker compose up -d --build` (the repo is bind-mounted: deploy = pull + rebuild, only when no job runs).
- MCP: systemd unit `showrunner-mcp`, `.venv/bin/python -m showrunner.mcp_server`, port 8787 behind Tailscale Funnel,
  public URL `https://main-network-interface.tail01346d.ts.net/mcp` (claude.ai connector, secret `MCP_TOKEN`).
  It reads `.env` itself. After a change in `showrunner/`: `git pull && sudo systemctl restart showrunner-mcp`.
- The skill: `python3 showrunner/tools/build_skills.py --zip outputs/skills` → upload `rzdhop-story.zip` to claude.ai.

## Tests

- Clips: `python -m pytest tests -q` (local: add `-n 4` with pytest-xdist). Two tests fail only when run as root
  (`*unwritable_directory*`): environment, not a bug.
- showrunner: `python3 -m pytest showrunner/tests -q -o addopts=""` (server tests skip without fastmcp). The server's
  own tests run in `.venv` with a pytest kept OUTSIDE it: `PYTHONPATH=<dir with pytest> .venv/bin/python -m pytest
  showrunner/tests -q -o addopts=""`. **Never pip/uv install into `.venv`: the live unit runs from it.**
- Skill: `python3 showrunner/tools/build_skills.py --check`. Dashboard: `cd web/dashboard && npm ci && npm run build`.
- Run the tests a change touches plus the area's guards; CI runs the full Clips suite on every push.

## Rules (Rida's, always)

- Code and comments in English. Nothing in `showrunner/` imports `clipping` or `web` (`test_boundaries.py`).
- Talk to Rida in plain words, in his language (French or English); no internal jargon (DEC numbers, stages) unless
  he asks. For complex work: propose a short staged plan and ask what is unclear before building. Answer format:
  short problem + root cause; per solution: description, full code (in context), why; a recap table
  (what / where / why / cost).
- Ask before changing how the system works. Never spend GPU money outside the skill's rules (cost said once per run,
  stop past 2× the estimate). No stills, Ken Burns, slowed clips, edge-tts or LLM API calls in the story pipeline:
  Claude writes every prompt, the connector only makes, checks, re-voices and cuts.
- Commit to `main` with a clear message; keep CI green.

## Records (keep them short and true)

- `.claude/CHECKPOINT.md` — the current state and the next step. **Replace** it, never append history.
- `.claude/DECISIONS.md` — one line per rule in force: `DEC-NNN | area | rule (date)`. A rule that changes is
  rewritten in place under a new number; a dead one is deleted. History lives in git.
- `.claude/ASSUMPTIONS.md` — only open questions, one line each, with how they get checked; delete when settled.
- `.claude/claude-action.log` — one line per change: `date | what | why | files`.
- `CHANGELOG.md` — user-facing changes.
