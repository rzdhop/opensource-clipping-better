# showrunner — AI stories, written by Claude, made on RunPod

Claude writes and directs a story in a claude.ai chat with the **rzdhop-story** skill
(`.claude/skills/rzdhop-story/`: `SKILL.md`, `steps/*.md`, `PROMPTS.md`). This package is the
`showrunner` MCP connector it uses as its hands: it makes the pictures, the speaking clips and the
voices on RunPod, checks each clip, and cuts the episode. It writes no prompt: Claude sends each one
as `values.prompt` of `comfy_submit`. Nothing here imports `clipping` or `web` (tested). Stdlib +
ffmpeg, plus fastmcp for the server.

```
showrunner/
  mcp_server.py           the connector: 21 tools (docs/MCP.md)
  mcp_auth.py             the claude.ai login (MCP_TOKEN)
  store.py                stories/<slug>/: files, locks, takes, cost ledger
  jobs.py                 GPU jobs into a story: submit, settle, journal, estimate
  runpod_client.py        RunPod Serverless /run /status client, payload builder, output saver
  comfy_templates.py      load/render the ComfyUI templates ({{placeholders}}, derived frame counts)
  verify.py               verify_take (speech-to-text on CPU), ffprobe/ffmpeg checks, contact sheets
  voice.py                locked voices: from an approved take, onto a clip (Chatterbox)
  assemble.py             the episode from the approved takes
  workflows/              the API-format graphs (generated by workflows/_build.py — edit the .py, not the .json)
    ltx25_i2v_speech      a clip from a keyframe, the line spoken in the prompt (LTX-2.5, joint audio)
    t2i_flux2_klein       a picture from a prompt (FLUX.2 klein)
    edit_flux2_klein_multiref  a picture from reference pictures + a prompt
    vc_chatterbox         a clip's voice converted to the character's locked voice
  worker/                 the RunPod image: Dockerfile, extra_model_paths.yaml, fill_volume.sh, ENDPOINT.md
  tools/build_skills.py   checks the skill folder and zips it for claude.ai
  tools/validate_workflows.py   checks every node/input of the templates against a ComfyUI source tree
  tests/                  offline tests (pytest)
```

## Run

- The server: `.venv/bin/python -m showrunner.mcp_server` (the `showrunner-mcp` unit on this host). Its
  settings are in `.env` (see `.env.example`, section "showrunner MCP server"). Never install into
  `.venv`: the live unit runs from it.
- The skill: `python3 showrunner/tools/build_skills.py --zip outputs/skills`, then upload
  `outputs/skills/rzdhop-story.zip` to claude.ai as a skill.
- Stories, clips, finals and voice files live in `stories/` on this host: back them up.

## The endpoints

1. Build and push the image: `docker build -t ghcr.io/rzdhop/showrunner-worker:0.1.0 -f showrunner/worker/Dockerfile showrunner/worker && docker push ...`
   It extends `ghcr.io/rzdhop/worker-comfyui-tts` (`docker/worker-comfyui-tts/`: Chatterbox + the handler
   patch that returns SaveAudio outputs) with the LTX model folders mapped on the volume.
2. A network volume ≥ 150 GB in the endpoints' datacenter; from a pod with it attached (mounted at
   `/workspace`): `HF_TOKEN=hf_... VOLUME_ROOT=/workspace bash showrunner/worker/fill_volume.sh` (a Read token of
   an account that accepted the license of `Lightricks/LTX-2.5`). Chatterbox weights:
   `docker/worker-comfyui-tts/fetch_weights.sh` if the volume does not have them yet.
3. The video endpoint (`RUNPOD_SHOWRUNNER_VIDEO_ENDPOINT_ID`) runs this image with the settings of
   `worker/ENDPOINT.md`; the image endpoint (`RUNPOD_IMAGE_ENDPOINT_ID`) runs FLUX.2 klein.
